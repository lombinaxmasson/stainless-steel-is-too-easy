## 维护方式

- 进度在总览维护，具体证据在对应计划卡记录，README 只保留阶段摘要。
- 已归档卡保留当时的验证结果与限制。后续解决旧缺口时，在当前总览注明解决记录，不把历史验证改写成新验证。
- “实现完成”“编译通过”“服务端加载通过”“客户端人工验收”分别记录；卡归档不自动代表四项全部完成。
- 灵感升级为实施任务时，再建立计划卡，并从灵感池链接过去；未讨论的想法不自动排期。
- 新增文档使用相对链接，并在这里登记用途，避免同一份进度在多处重复维护。
